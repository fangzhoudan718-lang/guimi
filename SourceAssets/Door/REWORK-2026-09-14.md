## 放逐 = 灵界流放（0.4.5.6）

SubworldLibrary 同一时间只加载一个世界，NPC 数组无法跨世界搬运，所以放逐分两步：
主世界把目标连同体节一起收走并记录种族/当前血量（`SpiritBanishSystem`），灵界载入时按记录在出生点附近重新投放。
玩家目标走的是灵界钥匙同一条路：服务器发 `SpiritBanishPlayer`，该客户端调用 `SubworldSystem.Enter<SpiritWorld>()`。

“已击败过的Boss”判定来自 `BossDefeatRegistry`：本世界击杀记录（随世界存档保存）+ 原版 `NPC.downed*` 旗标，
所以装模组之前打赢过的原版 Boss 也认。未击败过的 Boss 以位格硬抗，改为 2 秒真硬控（`hardStunTicks`，完全跳过 AI）。

门扉用 `DoorAuthorityVisual.ai[1]` 作为延迟，读出“开门 → 目标被吞下 → 关门”的顺序；开关门各有 `SoundID.DoorOpen` / `DoorClosed`。
放逐玩家只在双方都开启 PvP 时生效，避免误伤队友。

### 空间牢笼的绘制层级与视差（0.4.5.8）

星系背景用 `ModProjectile.DrawBehind` 登记到 `behindNPCs`：盖住地形与墙体，但留在生物、玩家之下，
所以被困在领域里的目标仍然看得见。早期版本挂在 `ModSystem.PostDrawTiles` 上，而那个钩子属于瓦片层
（官方文档：画完 Tiles 之后、用于类似电线的叠加层），启用渲染目标时会连同瓦片一起盖到实体上面。

视差来自观察者相对领域中心的偏移：底盘固定不动（切口边缘因此永远是同一个圆），
远景星野按 0.026、近景星野按 0.068 反方向平移，最多 700 像素位移。两层遮罩半径比底盘小 49 像素，
所以无论怎么平移都不会越过切口——这在 `Build-SpatialDomainLayers.ps1` 里有注释说明。
| 撕裂空间 | 剑气刃形的裂口开在鼠标处，长轴与“玩家→鼠标”方向垂直；存在600 tick（10秒）；开缝首刀全额，之后每30 tick按25%余波结算；玩家碰撞箱碰到裂口会被随机传送到同一施法者的另一条裂口，离开所有裂口后才重新解锁（`riftTeleportLocked`）；冷却2秒、消耗500灵性 |

### 维度之视“放出玩具”修复（0.4.6.1）

原来的放出判定是 `HasOwnedPocket`：只认收纳中的目标（`pocketTicks > 0`）。而收纳只有 180 tick（3 秒），
缩小却持续 720 tick（12 秒），所以玩家在 3 秒之后再按键时找不到“自己的口袋”，会掉进重新施放的流程并被冷却挡下——
看起来就是“按了没反应”。

现在判定改成 `HasOwnedToy`：`pocketOwner` 匹配且 `pocketTicks > 0 || miniatureTicks > 0`，
也就是只要目标还是这位施法者的玩具就能挪。`ReleasePocket` 不再清空 `pocketOwner`，
归属一直保留到缩小结束、体型恢复时才解除，所以整个玩具化期间都可以反复按 B 把玩具丢到鼠标处。

裂口改成剑气刃形：生成脚本用「中段等宽 + 直线收锋到尖点 + 每 5 行换一次的角状缺口」代替原来的椭圆，
轮廓是锐角刃口而不是圆头；亮刃线只有 1 像素且不加色混合，仍然不发光。
| 维度之视 | 3秒收纳/12秒缩小；收纳中再按在鼠标空地免费释放并关闭捕获领域，Boss仅5秒弱化 |
| 人物再现 | 2/3位已记录投影，各一次冲击/齐射/贯刺/追击；齐射分摊伤害，不生成未知敌对弹幕 |
| 时空迷宫 | 十二扇门围成半径480的旋转圆环，持续600 tick；圈内所有生物（含Boss）每 tick 绕圆心旋转 2π/240，位置与速度一起转，所以分节类Boss是整体转动而不会被拉断 |
| 空间破碎 | 半径720的黑洞：120 tick 成形 → 150 tick 持续牵引（Boss 吃一半牵引，位置也轻拽）→ 45 tick 凝聚，最后 14 tick 结算一次巨量伤害；全程每 10 tick 补一次震屏。消耗100000灵性、冷却120秒 |

## 时空迷宫 / 空间破碎重做（0.4.7.0）

- 时空迷宫（10000灵性，600 tick）：十二扇门围成半径480的圆环，以 2π/240 rad/tick 旋转；
  圈内所有生物（含 Boss）每个 tick 都把「相对圆心的位置向量」和速度一起旋转同样的角度，
  所以是整体刚性转动，分节类 Boss 不会被扯断。视觉由 `DoorDomainProjectile` 的 Kind 2 分支绘制，
  圆环转速与生物的“钟表指针”转速一致。
- 空间破碎（50000灵性，315 tick）：鼠标处张开半径720的黑洞。阶段划分见上表；
  牵引同时给速度冲量与位置轻拽，逃出范围的会被拉回边界内侧。震屏用
  `PunchCameraModifier` 每10 tick 补一次同名条目，形成连绵震动。视觉是
  `BlackHoleCore`（固定视界 + 光子环）+ 两条反向旋转的 `BlackHoleRing`（预先压扁的吸积盘），
  不写着色器就得到陀螺式的 3D 涡旋。

## 灾厄适配补全（0.4.7.0）

原先 `CalamityPotionLock` 只登记了七条途径（太阳/愚者/猎人/月亮/掠夺者/魔女/命运），
**巨人**与**门**两条途径的魔药完全没进表，所以开灾厄适配模式时它们不受任何进度限制。

现在改成「按序列查表」：`SequenceForPotion` 返回魔药对应的目标序列，
`RequirementText` 返回该序列的门槛，`CanUseItem` 与 `ModifyTooltips` 共用这两者——
工具提示会直接写出还缺哪个 Boss。九条途径共 81 瓶魔药全部纳入。

进度表（灾厄专属 Boss 只作为**替代**条件，多一条通关路径而不是额外加锁）：

| 序列 | 门槛 |
|---|---|
| 9 | 无 |
| 8 | 克苏鲁之眼 或 荒漠灾虫 |
| 7 | 世界吞噬者/克苏鲁之脑 或 腐巢意志/血肉宿主 |
| 6 | 骷髅王 |
| 5 | 血肉墙（进入困难模式） |
| 4 | 月球领主 |
| 3 | 亵渎天神（没装灾厄时退回月球领主） |
| 2 | 神之吞噬者 |
| 1 | 丛林龙，犽戎 |

`CalamityDowned` 对 `GetBossDowned` 做了 try/catch：万一灾厄改了内部名字，只会少一条替代路径，不会把玩家永久卡住。

## 时空迷宫修复与黑洞升级（0.4.7.1）

**迷宫“转一下就掉下去”的原因**：原来的实现只在 `距离 <= mazeRadius` 时才旋转，而圆环通常开在半空，
重力与生物自身 AI 几个 tick 内就把它们推到了圆外——一旦出圈，旋转判定直接失效，看起来就是“转一下然后掉下去”。

现在改成先拦后转：越界的会被拉回边界内侧并抵消一切向外的速度（重力也算），再额外每 tick 衰减 14% 的垂直速度，
避免一路沉到圆底贴边打滑；最后才把「相对圆心的位置向量」与速度一起旋转 2π/240。

**弹幕也跟着转**：新增 `DoorMazeGlobalProjectile.PostAI`，圈内飞行的弹幕同样绕圆心旋转。
门途径自己的弹幕（黑洞、领域、裂隙、门扉）是场地本身，自转只会看起来坏掉，所以整组跳过。

**黑洞升级**：

- 新增 `BlackHoleLens`（320×320、弧半径 145 的圆）——视界上下两道引力透镜弧，是“光被弯折”的关键读数。
  第一版把它做成了 320×160 的椭圆，弧线恰好落在视界内部被完全遮住，已改为正圆。
- `DrawInfallingStreaks`：30 道物质沿螺旋线掉进奇点，越往里越快越暗。
- **删掉了时空网格与螺旋辐条**（`DrawSpaceWarp` 与 `DoorVisuals.Line`）：那套细亮线在实机里读起来就是霓虹，
  和本模组一贯的克制方向相反。黑洞的“张力”改成靠**大块明暗对比 + 前后遮挡**来做，而不是靠线：
  - 引力井：两层极暗的柔雾（`Haze` + `Ink`）把周围吃掉，范围环也压成暗色，只做读数。
  - 吸积盘画两遍：`BlackHoleRing`（整圈，先画，被视界挡住远端）+ `BlackHoleRingFront`（只有下缘半环，画在球体之前）。
    圆盘从球体后方绕到前方，这一笔是整张图“立起来”的关键。
  - 盘面改成绕视线缓慢摆动（`tilt = sin(age * 0.012) * 0.42`，±24°）的进动，而不是整圈乱转。
  - 掉进奇点的物质从尖角 `Shard` 换成柔和的 `Mote` 尘点，角速度随进度平方上升，读起来是被越拧越紧地卷进去。
